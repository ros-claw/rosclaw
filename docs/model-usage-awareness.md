# Opt-in runtime model-usage awareness

Add `modelUsageAwareness` to the existing tool-call policy, with exactly:

```json
{"version":1,"lifetime":"runtime","inclusiveInputLimit":1500000,"outputLimit":16384,"deliveryReserveInput":10000,"deliveryReserveOutput":2000}
```

Limits must be positive safe integers; reserves are nonnegative safe integers no larger than their respective limits. Integer-valued JSON floats are accepted. Unknown or missing keys, booleans, null, arrays and invalid numbers fail before SDK/auth startup in both CLIs and the shared factory.

Omission leaves the previous tool policy unchanged. This observer does not grant tools, change admission counters, extend permissions, change the policy digest, interrupt execution, predict the next request, impose provider hard caps, or make extra RPCs. `visibleBudget` controls only the original full/compact tool notices; awareness independently enables its own notice.

`ROSCLAW_MODEL_USAGE_JSON:` appears at existing before-agent-start and tool-result boundaries. The exact fields are version, runtimeGeneration, sequence, completedMainRequests, knownInclusiveInput, knownOutput, remainingInputUpperBound, remainingOutputUpperBound, pendingMainRequests, unknownUsageRequests, unaccountedCompaction and reserveState. Counts are nonnegative safe integers. Remaining values are max(0, limit-known), upper bounds rather than measured remaining capacity. UNKNOWN usage preserves valid component lowerbounds, never invents a measurement of zero. Input sums input+cacheRead+cacheWrite; cacheWrite1h is a subset, never added again. Output is separate. Error/aborted initialized zeros are not trusted measurements.

The SDK clones message_start objects: settlement uses ordered public assistant lifecycle and current session association, not start===end. A WeakSet rejects replayed final objects; equal timestamps and usage on distinct requests count separately. Settlement at message_end occurs before tool results and the next internal request. A new factory creates a fresh generation. Session starts do not scan or bill history; unfinished associations become unknown. Compaction marks unaccountedCompaction; this is not a complete provider-cost ledger.

reserveState is normal, finish_delivery (advisory testing/summary/report/STOP priority), or unknown. It neither authorizes effects nor claims delivery completion. Reserved usage marker lines in system/tool text are replaced; ordinary text, details and public tool_execution_end structuredContent remain intact. Original SDK session history omits structuredContent, and its ABI is not extended.

SOURCE tests use installed SDK AgentSession with local inert stream injection and synthetic credentials only. No paid provider, ROS, container, physics or hardware execution is authorized. Only artificial duplicate and late callbacks are negative replay controls. Current notices are observed in the actual stream's leading system message, where PI normalizes the effective before_agent_start systemPrompt (there is no context.systemPrompt property); historical context.messages are observed separately, since tool notices can be stale and the disabled baseline deliberately retains a forged marker. New/resume/fork use public AgentSessionRuntime methods. Manual compact uses two persisted SDK turns and a one-token keep window, asserts the real session_before_compact preparation event, and accepts only exact offline hook cancellation. This verifies compaction entry/accounting uncertainty, not model-generated summarization or all lifecycle races. Public tool_execution_end details and structuredContent are checked in both enabled and omitted-policy modes. Checker receipts, rather than this description, determine current validation status.
