# Continue a recorded native session

`rosclaw continue` selects the most recently modified valid recorded Pi session across this ROSClaw HOME. Python queries the installed public `SessionManager.listAll` through an offline metadata entry before creating the service. Its exact native ID drives mission-mode/profile lookup, and its exact path is passed to Node. Node opens the record before resolving task context, so an enclosing Git root cannot silently replace the recorded workspace and allocate a new continuation UUID.

Normal new chat still uses explicit workspace, Git inference, and persistent workspace rules. Direct native `--continue` uses the same global recorded-session selector. Invalid files excluded by public SDK discovery are not selected. No valid history returns an explicit error and directs the user to create a new chat; it no longer creates a fresh session under the word “continue.” Missing/empty explicit resume paths are rejected rather than initialized. Failed target selection does not persist a workspace change. An explicitly supplied workspace remains an explicit user override; implicit Git inference cannot override a recorded continuation.

The metadata child sets `PI_OFFLINE=1`, reads session metadata only, and does not construct an agent session or send a model request. The ordinary native agent keeps its original provider/network configuration. A single selected target is reused for mode routing and actual opening; no second directory-filtered lookup occurs in Python-launched continuation.

Evidence began with an exact-once isolated Kimi F06 episode: its original precise workspace session was followed by a new enclosing-repo UUID after normal quit and `continue`. The original episode remains a strict UUID failure plus an operator multiple-session parse failure. Offline generic fixtures reproduce the old selection using installed PI1.0.3 and prove the new global target, recorded workspace, mode binding, and byte-preserving failures. They do not replace a fresh native same-UUID end-to-end validation, which requires its own budget and GO. No hardware, ROS runtime, or physical acceptance is inferred.
