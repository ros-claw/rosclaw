# Phase 8 C13：全身状态技能岛记忆、运行时闭环与高球局部搜索

日期：2026-08-08
范围：SIM_ONLY；MuJoCo 动力学与 ONNX 推理由 CPU 执行，4 张 RTX A6000 仅用于并行实验编排和 EGL 渲染；没有真实机器人命令、在线热更新或晋级授权。

## 1. 结论先行

本轮完成的突破不是“把 seed 0 的脚法复制给所有种子”，而是第一次把 G1 的完整交接状态、已验证的接触动作、触球相位和恢复参数封装成可执行的技能岛记忆，并接入 ROSClaw 产品 CLI 与物理运行时：

```text
历史严格证据
  → 70 维全身交接状态原型
  → 任务/本体/轨迹/实现哈希绑定
  → 支持半径与歧义间隔门
  → 检索已登记 SONIC 方案
  → 现场全身状态复核
  → 动作 + 接触相位 + 恢复阻尼执行
  → 严格重放与新证据回写
```

两个已登记技能岛均以状态距离 `0.0` 严格复现，连续触球、越过 6 m 球门线、不摔倒、踢后零后退。未登记 seed 36 在不允许重规划时被 CLI 以退出码 2 拒绝，且不产生证据目录；启用 `--select-best-registered-skill` 时，系统在仿真前明确改选 seed 0 的成熟整套方案，而不是把 seed 0 的接触动作广播到 seed 36 的未知交接状态。

严格射门任务仍未通过。两次左上高目标误差分别为 `0.416487 m` 与 `0.481124 m`，高于 `0.16 m` 精度半径；过门线高度分别为 `0.945241 m` 与 `0.869363 m`，低于目标 `1.35 m`。因此这些是 development skill islands，不是 sealed generalization 或 promotion evidence。

## 2. 为什么 C12 后需要技能岛记忆

C12 已证明：

- seed 0 与 seed 32 可分别找到安全、连续、越过高位球门线的动作；
- seeds 33–36 的密封评估没有形成可泛化的第三技能岛；
- 同一接触动作跨 SONIC 计划广播会显著失败；
- 接触中心相差数帧就可能落入完全不同的接触分支。

因此，“一个成功动作 + 最近一次 reward”不足以构成自进化。真正需要保存的是：**在什么身体状态、什么任务上下文中，哪一整套方案已被物理证据支持**。

## 3. 实现内容

### 3.1 70 维全身交接状态

新增 `growth/ballistic_skill_memory.py`，交接状态由四个物理组构成：

| 状态组 | 维数 | 固定归一化尺度 |
|---|---:|---|
| 骨盆位置 + RPY | 6 | 位置 `0.15/0.15/0.08 m`，姿态 `0.15 rad` |
| 29 关节位置 | 29 | `0.25 rad` |
| 骨盆线速度 + 角速度 | 6 | `0.30 m/s` 与 `0.50 rad/s` |
| 29 关节速度 | 29 | `0.80 rad/s` |

距离采用四组等权的 normalized RMS，避免 29 维关节向量仅凭维数淹没骨盆姿态或速度信息。

### 3.2 证据与安全边界

训练器要求至少两个合格技能证据和四个拒绝状态，并逐项验证：

- 严格重放为真；
- 轨迹文件存在、大小受限且 SHA-256 与证据一致；
- Body、实现和任务上下文一致；
- 合格技能必须 hard-safe、连续触球、越过球门线、误差不大于 `0.75 m`，且过线高度不低于 `0.65 m`；
- 拒绝状态不得反过来满足技能条件；
- 记忆明确标记为 `SIM_ONLY_DEVELOPMENT`，禁止真实硬件、直接力矩、在线热切换和晋级。

任务上下文哈希绑定球门、助跑、SONIC、候选策略和除技能动作之外的 flow 配置。修改目标高度、球门距离或控制上下文后，旧技能记忆会 fail closed，不能冒充可迁移技能。

### 3.3 选择门

当前发展版门限为：

- 最大支持距离：`0.35`；
- 最小第一/第二原型距离差：`0.05`；
- 两个技能原型距离：`0.221618`；
- seeds 33–36 到最近原型的最小距离：`0.716140`。

超过支持半径返回 `OUT_OF_DISTRIBUTION_HANDOFF`；两个技能岛无法区分时返回 `AMBIGUOUS_SKILL_ISLAND`。两者都不会执行未知动作。

### 3.4 ROSClaw 闭环接入

新增产品命令：

- `growth ballistic-skill-memory`：从严格证据训练并落盘技能记忆；
- `goalforge free-kick-showcase run --ballistic-skill-memory ...`：指定已登记 SONIC 技能；
- `--select-best-registered-skill`：在必须完成射门的任务中，先检索最低误差的完整成熟方案。

运行时在 SONIC→射门交接处重新读取 MuJoCo 的骨盆位姿、29 关节位置、骨盆速度和 29 关节速度，再执行一次支持域选择。只有现场选择出的 skill id、planner seed、六关节残差、接触帧和恢复阻尼全部与记忆一致时才继续。

证据新增 `ballistic_skill_memory_executed`、skill id、最近距离和距离间隔；视频渲染器新增 `FULL-STATE SKILL MEMORY` 与状态距离叠字。

## 6. 四卡局部搜索：哪些方向没有突破

所有下列试验均为严格重放、连续、不摔倒、踢后零后退：

| 变量 | 目标误差 | 过线高度 | 结论 |
|---|---:|---:|---|
| 当前基准：aim z -0.20，pitch 0.18，synergy 0.18 | 0.405250 m | 0.956246 m | 本地历史最优 |
| aim z -0.25 | 1.050116 m | 0.301099 m | 接触分支突变，显著恶化 |
| aim z -0.30 | 0.443105 m | 0.912844 m | 边界仍不如基准 |
| synergy 0.14 | 无过线 | 无 | 射程不足 |
| synergy 0.16 | 0.606137 m | 0.744199 m | 恶化 |
| synergy 0.20 | 0.573148 m | 0.785662 m | 恶化 |
| pitch 0.16 | 0.730369 m | 0.619696 m | 恶化 |

这组负结果很重要：当前瓶颈不能再靠围绕同一姿态模板做小幅人工角度扫描解决。动作空间在接触边界附近不平滑，误差应由触球点高度、足端三维速度、接触法向/冲量与相位不确定性来解释。

## 9. 下一轮的工程突破点

1. 在轨迹中新增触球瞬间足端位置/线速度/角速度、接触法向、法向与切向冲量、球的出射速度标签，建立可学习的 contact observer。
2. 把 actor 从“70 维状态→六关节残差”扩展为“70 维状态 + 目标点→接触帧分布 + 足端接触目标 + 有界残差”，显式表达相位不确定性。
3. reward 同时约束目标 yz 误差、连续性、摔倒、后退、恢复期骨盆速度和关节速度，避免用更大身体冲击换球高。
4. 每个技能岛周围采样多个 SONIC 方案和扰动状态；用离线 actor-critic 学局部策略，再由支持域门决定是否允许在线小步更新。
5. 新候选必须先在开发集超过 `0.405250 m`，再做未见 seeds 密封评估；未达到 `0.16 m` 之前不声称精准左上角成功。

MotionDecode 更适合改善自然全身协调与动作先验，但不能单独提供足球接触动力学。下一轮应让 MotionDecode prior 负责“像人”，contact observer 与目标条件 actor 负责“踢准”，技能岛门负责“只在知道自己会的时候执行”。
