# PI 1.1 model tool registration and activation

`createAgentSessionFromServices({ tools })` is a *lifetime registration allowlist*, not a one-turn active list. The old static intersection permanently rejected later capability registration. The runtime now omits `tools` for the no-policy legacy default, keeping the complete SDK/custom schema and future materialized tools. With an explicit policy it passes a clone of **all** allowed names (including not-yet-available capability names) as registration authorization, but registers only allowed static custom definitions. `[]` remains explicitly empty.

Activation is separate: the first session, session start, and resume activate only available static names intersected with the immutable policy. A capability snapshot registers only policy-authorized materialized definitions; active names are rebuilt from the current snapshot, so unavailable/withdrawn capabilities and foreign names in a policy do not enter the model surface. No-policy snapshots retain their full dynamic surface. The independent execution-time tool-call budget still rejects synthetic/excluded calls; no change to its path/command/count limits, kernel dispatch, or physical authorization.

The local test exercises the registration-versus-activation distinction, policy clone, explicit empty and default runtime startup; the public regression checks actual provider serialization and changing capability snapshots. This source-only change is not evidence of real robot execution.

## Session-owned UI lifecycle

PI 1.1 replaces the extension context on `/new` while retaining the shared ProductStateCenter and LocaleManager. Discarding the unsubscribe returned by those centers left old chrome and widget closures alive; the reproduced failure was an old UI getter reached through ActiveSessionContext → ProductStateCenter. This is not evidence that tool policy caused the bug.

The extension now releases all three center subscriptions and the locale subscription before replacement/disposal, invalidates their generation, clears startup/periodic probe timers, and drops the current context and chrome closure. Duplicate starts replace these resources rather than accumulating them. Pending resume-report, bootstrap/status-widget, activity-widget and capability-refresh results check their generation before accessing UI or activating tools. Shared state-center probes may finish and update shared facts; they cannot call disposed UI subscribers. Shutdown also stops the existing operation watcher and provider activity/watchdog timers without changing cancellation authority or provider handlers. Coordinator startup notices are generation-bound.

The lifecycle unit test uses the real extension, center and locale with deferred status queries and a disposed-getter sentinel. It checks duplicate listener counts, late completions, current chrome/locale/kit/widget responsiveness and cancelled startup probes. It is not a substitute for the public actual compiled Main/PI two-`/new` regression. Build/check/regression receipts are recorded separately against final source hashes; no source is changed after those gates.

## Host-owned pending preflight cancellation

PI 1.1 `abort()` stops an active run but does not cancel a prompt awaiting `before_agent_start`. A single synchronous, nonexported installer now binds only the session's public `prompt` and `abort`, immediately after each original factory result and before publishing `lateSession`. Each prompt owns a distinct pending identity. Abort marks the identities already pending synchronously and still delegates to the original SDK abort. Subsequent prompts are not poisoned. A typed `preflightResult` composition retains the identity through the original callback and checks cancellation both before and after it: only a cancelled `started` disposition throws its own host sentinel before the SDK enters its agent run. An original callback that aborts and then throws keeps its exact foreign error. The wrapper catches only that exact object; same-message/name/shape foreign errors are not cancellation authority. Normal handled/queued/started callbacks and their exceptions retain their original behavior, and already dispatched runs remain the SDK's responsibility. Rejected prompts remove their identity; a resolved prompt without a disposition retains its accepted-but-deferred identity. A WeakMap keyed only by host-composed public options carries the same identity through the original SDK's recursive `agent_settled` continuation. Terminal dispositions remove both pending authority and the continuation mapping. The caller's original options are never used as a sticky cancellation key.

The extension captures its UI generation, current-context identity, published session identity and session/mission IDs before either await. Immediately after capability refresh it checks replacement before reading `ctx.model`; immediately after context fetch it checks again before applying an envelope, marking stale, patching the active run, or injecting obsolete context. Merely returning from the extension is not SDK cancellation: the runtime's preflight boundary is also required. No broad catch, SDK patch, private field, provider interception, message suppression, other handler change, writer-ownership change or tool-catalog change is part of this fix.

New tests execute the production installer in isolation for concurrent identities, all three normal callback dispositions and exact callback/SDK errors, later live prompts and delegated in-run abort. These adapter tests are explicitly not substitutes for SDK acceptance. Original SDK runtime tests exercise handled callback errors and post-abort usability with restrictive activation and existing ownership. Deferred real-extension tests cover both capability and context replacement, zero disposed model reads, zero obsolete active-state mutation and current responsiveness. The final public regression supplies original compiled Main/SDK serialization, serial two-new and rapid capability/context acceptance; its actual receipts, not this description or historical component passes, determine the current outcome. Historical whole37327/11215 failures and whole93497 provider failure remain failures; Root's 11-case seam and serial component passes are not promoted to whole acceptance.
