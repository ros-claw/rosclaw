# Read-only engineering cases: first Physical ACI delivery

This phase implements a pure `RosEngineeringCaseV1` compiler and offline replay adapter, not a new runtime, live ROS tool, repair executor or model pilot. It takes an already sealed RosSystemModel, original URDF bytes, explicit navigation requirements, original source/Body review context and a review clock. No evaluation fault label is an input.

The compiler reuses existing navigation-candidate and navigation diagnosis logic, derives original collision geometry and produces typed constraint differences for localization TF, scan freshness, required lifecycle, costmap circle envelope and exclusive velocity routes. Full `navigation_readiness` remains a separate existing operator gate: this diagnostic case does not rerun or replace it. Source binding reports are checked for schema, snapshot, clock and expected run/Body consistency, with missing or mismatched evidence kept UNKNOWN/VIOLATED.

Each claim has stable original JSON-pointer/value-hash references. Derived candidate/source documents are separately retained with content-addressed refs. Measured, inferred and unknown classifications stay explicit. Replaying the same sealed inputs at the same explicit original clock yields the same case hash; serialized tampering is rejected. The summary provides decision gaps and small evidence refs without embedding the full graph.

Known fault states do not automatically prove root causes. A stale scan leads to a bridge/publisher check, not an invented paused-bridge diagnosis. Inactive lifecycle leads to managed-node/transition investigation. Competing velocity endpoints require ownership review and never compile a command to disable an arbitrary node. Missing map-to-odom plus observed tf_broadcast=false yields only a conditional staging candidate requiring independent publisher-authority and lifecycle checks. Costmap radius candidates preserve original geometry and require full effective-footprint review.

All cases keep `current_authority=NONE`, `admission=NOT_ADMITTED`, `current_l1=NOT_EVALUATED`. Candidate intents are staging-only and `applicable_now=false`; they issue no permit or action and do not change any input. SEALED_REPLAY is historical diagnosis, not live readiness. A candidate PROPOSED status cannot promote the case to L1.

Validation: 20 focused tests cover five faults, healthy state, an unseen fault combination, contradictory TF/geometry, stale/future evidence, wrong source/run, deterministic hash/reference replay, tampering, typed-value rejection and architecture imports. Actual 54-snapshot replay identifies the corresponding known constraint gaps without model/World calls; summaries are below 2,500 characters. Healthy J100 snapshots still have UNKNOWN source/TF checks where the supplied observations do not provide the necessary proof. This is intentional, not a false READY claim.

Reproduce using `PYTHONPATH=src:. .venv/bin/python -m benchmarks.ros_expert_ablation.replay_engineering_cases ORIGINAL_STUDY OUTSIDE_INPUT_OUTPUT`. Original model results remain unchanged. Compact replay results are in `replay-review.json`; full local case/summary artifacts preserve reference details.

Next phases are separately scoped typed ACI/staging integration, current-state context/Memory integration, and an independently preregistered pilot plus deterministic-only baseline. No model benefit, reduced model turns, physical transfer or superiority over the complete Codex product is claimed here. Navigation controller, rosclawd, safety thresholds and original G5 runner/tool contracts are unchanged.
