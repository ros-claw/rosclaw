# Same-model experiment implementation, not executed results

The protocol allocates 54 distinct episodes: six cases × seeds 101/202/303 ×
A/B/C, paired by case/seed with randomized pair and arm order. Generic task file
inspection and restricted staging proposals are shared. B/C additionally use
the existing pure ROS system-model, diagnosis and navigation-candidate reviewers.
Only C can query the actual training Memory store. Same-case evaluation answers,
evaluation runs and unverified/mismatched provenance are rejected before context
admission. Current J100 training examples are not admitted for J100 onboarding.

The model turn client uses pinned Codex CLI 0.162.1, requested model gpt-6.1-sol
and medium effort, with fresh temporary authenticated state, ignored user config,
no repository/MCP activation, read-only policy and disabled native execution,
apps/browser/multi-agent/Memory import tools. External structured tools mediate
all inspection, staging proposals and SDK validation. Agent processes never
instantiate Runtime, register executors or open ROS/DDS. Existing SDK operators
and canonical rosclawd own all actual simulation navigation.

A scratch-container client was built offline and its version/tools checked, but
container networking/routing failed. Those original failures are preserved.
Two host process connectivity checks actually completed with original provider
usage, including cache/reasoning token fields. They are not formal benchmark
episodes. Host process tool isolation is explicitly distinguished from container
isolation. The CLI does not report hidden server model revision, numeric sampling
temperature or monetary cost; these remain UNKNOWN, not fabricated values.
The same requested route/effort/default sampling policy applies to all arms.

The runner enforces shared 300 second wall, 12 tool call, two fresh-World test,
48,000 prompt-byte and 64,000 observed context-token bounds. A model's finish or
success text cannot replace independent original fresh L1, canonical receipts
and physical stop evidence. Missing actual usage is MISSING_DATA, never zero.
A positive physical result outside the experiment time budget does not pass.
Restricted patches cannot write URDF/Body/controllers, add fake TF or shrink a
costmap circle below the independently derived original URDF envelope.

The isolated onboarding capture records a fresh unbound PROPOSED candidate with
zero admission, lease updates, commands or navigation goals. L1 remains
NOT_EVALUATED. Engineering fault captures retain their UNKNOWN/BLOCKED assessment.
Model proposals must subsequently enter new staging and a new World with the
existing complete Body/L1/canonical-L2 independent acceptance path.

The model/World experiment begins only after G3/G4 prerequisites are frozen and
accepted. Allocation, actual evaluator integration, provenance filtering,
original logs, failures and statistical report must be independently checked.
No formal 54-episode model result, Memory benefit, full v1 or hardware acceptance
is asserted by these protocol and runner software tests.

The external sdk_operator module accepts explicit operator material/recovery
paths, retains original preparation failures, allows at most two fresh zero-
admission preparation Worlds, and evaluates each proposal through the existing
canonical SDK fixture plus independent original source/stop reviewers. Cleanup
requires exact container ID, evidence mount, pinned SDK image and network-none.
It never turns World termination into physical-stop evidence. Formal source/run
seeds, all helper hashes and the actual training store must be frozen before the
54-episode study. Native CLI tool deviations fail the external protocol while
retaining any provider-reported usage. Model-referenced Memory aliases must have
actually passed admission before the proposal. Rejected-record labels/counts
are kept in the operator audit, preventing the admission filter from exposing
the hidden evaluation class to the model.
