# P3c historical mechanism Memory

The earlier C adapter retrieved diagnosis summaries. This adds a pure typed
historical mechanism record and an operator-only distiller that rechecks the
original before/after/rollback evidence before storing anything in a **new**
existing MemoryInterface database. Frozen G5 data and its runner are unchanged.

A record binds the original episode SHA, three distinct World identities,
original L1, two distinct canonical completed SIM receipts, independent
stop/contact/source review and all original staging/URDF/SDF assets. URDF must
match exactly. SDF must match after replacing only the two declared observer
plugins' run IDs, and only after checking those IDs against original settings.
No geometry, physics, controller or other SDF content is normalized away.
The actual allowed staging delta selects one of five closed mechanisms without
using a gold fault label. Measured observations must support that mechanism.
Rollback must restore staging. A derived candidate never grants current L1 or
action authority and never transfers geometry to a different original URDF.

The current repair is compiled again. Historical namespaces, numeric radii,
node lists and process identities are not copied into staging. Manager membership
is derived from current original observations while preserving the current list
prefix. Endpoint removal needs current host ownership proof. The existing typed
compiler, TaskTools whitelist and explicit SDK validation remain mandatory.

`MechanismTrainingQuery` uses the existing actual Memory retrieval interface,
a frozen typed allowlist and original artifact SHA checks. It retains the old
same-case/onboarding/URDF/evaluation-run exclusions; a new split requires separate
preregistration. Corrupted record labels cannot bypass exclusions. No evaluation
result is added to training. C receives at most two short admitted mechanism
priors. Its explicit `propose_memory_repair` binds an actually admitted reference,
recompiles a current intent, records the selected reference and proposes staging
only. A/B and unadmitted references are rejected. Reference selection and even a
successful future SDK test would not by themselves establish causal Memory gain.

The KNOW export uses the existing KnowledgeUnitV2 schema: mechanism,
implementation, applicability, contraindications and pinned evidence references.
It stays **draft/generated with zero promoted confidence**, separate from the
Memory store. Publication and reliable knowledge admission belong to the existing
KNOW workflow; this adapter never promotes a generated generalization silently.
HOW remains advisory through existing knowledge contracts. Optional external
service/package qualification is reported separately from Core contract tests.

Development verification reads five actual historical three-World episodes,
creates and reopens a new SQLite Memory store, compares full typed records,
performs actual provenance-filtered retrieval and recompiles current static
proposals. It starts no models or Worlds and proves no model/Memory benefit.
Unit controls cover changed original bytes, history tampering, rollback drift,
wrong World/receipt identities, healthy current state, unadmitted Memory refs,
Body/run/case exclusions and generated knowledge status. Original duration is
measured capture-to-receipt wall time, not a model or tool phase clock.
