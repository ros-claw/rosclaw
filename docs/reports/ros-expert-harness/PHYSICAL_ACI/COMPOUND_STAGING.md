# Compound staging development

The opt-in common typed `ros_engineer.propose_compound_repair` accepts two to
five distinct existing semantic intents. Every component is compiled against
the same original case, model, requirements, staging and ownership review.
No component receives another component's proposed configuration as its base.

The compiler rejects duplicate kinds, overlapping decoded JSON pointer paths,
unknown or healthy constraints, source mismatch and changed evidence. It retains
the existing eight-field operator patch budget. Ordered component proposal IDs,
original before values, deduplicated evidence and preconditions, exact reverse
rollback and unchanged fresh World/L1/two canonical receipts/stop/source proof
obligations bind the combined proposal. The existing TaskTools whitelist checks
the whole proposal independently. Original staging is never mutated.

No new Runtime, ROS connection, authority or navigation controller is introduced.
This source prepares genuinely held-out combinations for a future separately
preregistered study. It does not change the frozen single-case pilot runner or
its allocation and does not itself establish model or Memory benefit.

The Expert decision card now exposes each non-satisfied invariant, expected
condition and explicitly inferred hypotheses, plus conditional candidate semantic
fields, values, evidence refs and preconditions. Candidate IDs alone did not
communicate the available decision to the frozen pilot model. Candidates remain
inferred, stage-only and not currently applicable/admitted; A still receives only
the common original-fact catalog. This card revision is not used in that pilot.


The new runner revision also binds provider schemas to the actual current case
hash and host-issued proposal/result/Memory references. Validation and explanation
choices are absent until their required references exist. All arms share this
phase discipline; the host still rechecks every binding against the original
case, so schema constraints confer no admission or permission. This addresses a
retained wrong-hash model request observed in the frozen pilot, without changing
that pilot or its original rejection.
