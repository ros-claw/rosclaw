# Conditional staging options

This opt-in interface separates static staging eligibility from physical
execution preconditions. A snapshot-supported semantic repair can form an
unexecuted hypothesis while fresh Body/source, full L1, canonical receipts,
independent stop/contact/source proofs remain pending. Unknown physics is never
reported as ready. Original source mismatch blocks every repair option.

`compile_staging_options` is a pure function over the original case, model,
requirements, staging and operator ownership review. Its typed content-addressed
options bind the same original case/snapshot/URDF/staging and minimal diff used by
the existing Repair Compiler. Lifecycle roles are derived from current observed
names; radius uses the existing deterministic baseline's conservative rounding;
endpoint changes require the current operator review. Unsupported mechanisms,
healthy or stale constraints yield no option. No private factory label is read.

B/C receive option previews; A retains common raw evidence and ordinary typed
repair tools. `ros_engineer.select_staging_options` selects one to five distinct
actual option refs, recomputes them, and delegates to the existing single or
compound repair path, including its independent TaskTools whitelist. Selection
registers a staging proposal only. Explicit SDK validation is still required and
finish remains report-only. Provider schemas bind actual current option refs.

Original full case and option catalogs are saved separately from bounded current
frames. Model frames retain the conditional diff and all pending physical proof
obligations while avoiding duplicate candidate descriptions and hashes.

The deterministic baseline has the same known mechanism information. Successful
selection of an obvious known option does not demonstrate LLM reasoning,
transfer, Memory benefit or superiority over full Codex. Frozen earlier pilots
are unchanged; any new real model evaluation requires independent registration.
This adds no Runtime, native ROS connection, execution gateway or permission.
