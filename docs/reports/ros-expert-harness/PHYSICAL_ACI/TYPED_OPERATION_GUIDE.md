# Explicit host operation effects

The opt-in external typed runner now supplies `HOST_OPERATION_GUIDE` alongside
current state and the evidence workbook. The existing response schema establishes
types and phase-bound references. The guide separately explains each currently
available operation's argument fields and actual host effects: original page or
slice reads, proposal registration without execution, a possible zero-goal probe
replica, an explicit costly SDK validation, recorded-result explanation, or report
termination. Descriptions are selected from the actual phase/arm schema, so absent
validation/result/Memory/option methods are not advertised as currently available.

The guide contains no fault label, Body value, historical literal, selected option
answer or execution credential. All arms receive the same descriptions for common
operations; only the already permitted Expert/Memory methods differ. Source-bound
staging registration is an unexecuted hypothesis and needs no motion authority.
No current L1/physical validity follows from reading historical records. Actual
SDK admission and verification remain unchanged and explicit; unavailable callbacks
cannot produce success. `finish` reports only.

Original recorded pilot requests contain operation types in their output schema,
but lack this complete effect-aware guide in their task prompt. The observed
reading loops motivate this change; they do not prove that missing descriptions
caused those loops. The guide is bounded to 6,500 characters and the full prompt
still has its existing 48,000-byte limit. Guide/schema generation is now included
in measured frame time. Full original events and tool artifacts remain separate.

Unit checks cover phase/arm/schema alignment, omitted methods, effect distinctions,
absence of case answers, bounds and report-only finish. Synthetic clients are not
actual model evaluations. Any further workflow probe or pilot must be independently
registered with its own task, allocation and stopping rule. Previous independent
pilots and historical calibration remain frozen; no model-efficiency benefit is
claimed by this engineering change.
