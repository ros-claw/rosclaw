# Typed Physical ACI — proposal/validation boundary

The P2 facade exposes operation-specific JSON **object** arguments for inspect_task, investigate, propose_repair, propose_onboarding, validate_proposal, explain_result and finish. Host-side discriminated validation is authoritative; a JSON-encoded argument string or extra permit/ROS-write field is rejected with an actionable example. This is an external benchmark/operator facade, not a new runtime or canonical MCP action endpoint. Original G5 runner/tools/results are unchanged.

The pure ROS repair compiler binds semantic intent to an immutable case, its sealed source model, explicit requirements and original staging values. It generates a minimal change list, rollback, original evidence refs and proof obligations. It checks the original URDF circle envelope, managed-node readback/current capture, observed interfaces and source mismatch. A paused-bridge remedy requires the actual staged pause policy; inactive lifecycle alone is insufficient. The existing TaskTools whitelist and typed field checks independently validate each proposed diff. No original file or current ROS system is mutated.

Only a host-pinned closed SDK ownership review can disable the declared **additional staging endpoint** in a new World. Review checks original run, owned process PID/argv, known fixture code SHA256, declared bringup, fixed SDK image, network-none and read-only source mount; the semantic compiler also requires its publisher to be a competing protected endpoint, never the selected controller/monitor. It does not authorize killing a live process or disabling a publisher by a string name. Generic unowned competing routes remain rejected.

`finish` only ends and reports. New-World validation is explicit, requires an injected existing SDK operator evaluator, pinned source/run identities and positive finite host-owned remaining budget (maximum 300 seconds), and is capped at two calls. Model arguments cannot supply a callback, budget, permit or executor. The operator continues to use full new L1 and canonical rosclawd actions, plus independent original physics/source/stop reviewers. Late or incomplete positive claims are retained as original evidence but not accepted. Existing dossiers keep NONE/NOT_ADMITTED/L1 NOT_EVALUATED even after a different World validates.

`investigate` presently indexes sealed evidence and declares NEEDS_OPERATOR_READ_ONLY_PROBE when a fresh check is needed. It never pretends that returning historical refs executed a live probe. A allows the common typed proposal interface without expert constraint explanations; B/C receive compact case gaps. Automatic Memory retrieval and a new bounded model-state loop belong to the separately scoped P3 phase and new preregistration.

Twenty focused tests cover typed objects, prohibited fields, minimal diff/rollback, geometry shrink, healthy/unknown cases, TF/lifecycle and observed onboarding, unowned/protected endpoints, stale manager facts, changed context, explicit budget, incomplete/late results and finish-without-validation. A scientific-float regression ensures temporary validator config uses YAML serialization rather than changing `1e-5` to a string through JSON/YAML roundtrip.

Offline scripted constraint replay on all 54 original snapshots yields 45 statically accepted repair proposals and nine observed-interface proposals. Decisions use constraints/actual staging, not evaluation case labels. This is a deterministic offline baseline, **not** 54 model successes or physical repairs. All original artifacts remain unchanged; original failed prototype replay is retained separately. Live SDK development acceptance, original CI and normal source/main integration remain separate gates. No model benefit or transfer claim follows from typed proposal admission alone.
