# Registered A/D baselines and common original facts

The new RSK clients now cover A/B/C/E model-tool allocations and the zero-model
D allocation. This is a same-model external-tool ablation. It is not a comparison
with the complete Codex product, and no scientific pilot is reported here.
Frozen G5, its 54 negative episodes, Core, ROS drivers and executors are unchanged.

## Common evidence and registration

All A/B/C/E interfaces offer identical `files.list` and bounded `files.read`
operations, in addition to existing common-evidence pages. Original strings,
lengths, SHA256, character offsets and returned slices remain in the trace.
A cannot call Expert investigation, staging-option selection, semantic repairs,
active probes or Memory. B has no active probe; C/E keep their registered probe
budget; only E has the audited historical concept query.

The common episode binding checks the same case, model, requirements, staging,
task, run, provider and per-case Memory policy for every arm. Actual episodes
add two explicit manifest references: `original_files` pins the original raw
TaskTools file dictionary; application episodes also pin `application_inputs`.
The latter binds original JSON key order as well as values because compiler
serialization preserves that order. Original run identity must match the case
or existing SDK operator. Inputs and original entry gates are rechecked before
host dispatch. Older incomplete manifests remain usable only as labelled
synthetic contracts; they cannot launch actual model/SDK episodes.

Application inputs include the reusable software template, installed component
manifests, request and four original files. Generic and Expert arms can read
identical strings. The compiled answer is not included in either original-file
catalog. Semantic case verdicts and private evaluation labels are not added to
the generic projection; independent case registration must audit the actual raw
corpus for accidental labels before any pilot.

## A: generic authored staging

`GenericRskACI` uses legacy A original-file tools and a new operation schema:

- `files.list` / `files.read`: the shared bounded original-file interface.
- `staging.propose_patch`: model-authored file, RFC6901 pointer and JSON value.
  The existing host whitelist, scalar types, minimum Body radius and protected
  endpoint ownership checks still apply. Duplicate targets and no-ops reject.
  The host records exact original values and rollback. It chooses no remedy.
- `staging.propose_application`: model-authored four file strings. This initial
  application comparison is deliberately limited to semantic equivalence with
  the same frozen current compiler profile. It does **not** accept or assess
  arbitrary otherwise-valid ROS applications.
- Existing common original-evidence reads, observed interface selection, explicit
  validation/explanation and finish remain available. No shell, native tools or
  direct ROS access is added.

Application equivalence preserves list order and scalar types, including double
versus integer and boolean versus number. Dictionary order and whitespace need
not match. The host seals the optional derived `navigation_requirements_hash`
and serializes an equivalent configuration; the model does not calculate a
cryptographic digest or guess YAML formatting. A mismatching application returns
no compiled answer or registered proposal. YAML aliases, duplicate keys,
malformed objects and nonfinite values reject. Actual file strings and their
SHA256 remain recorded. The application scope and this host policy check must
be disclosed in comparisons; this is not a general configuration synthesizer.

The existing SDK callback remains the only validation path. A valid staged
proposal does not grant admission. Fresh source/run, independent L1, two canonical
receipts, stop/contact and wall-budget rules are shared with the Expert path.
Synthetic clients cannot use or acquire SDK callbacks.

## D: current deterministic system

`run_rsk_deterministic_episode` binds a registered D ordinal and the same common
facts before selecting a request. It invokes no model and uses no Memory or
active-probe World. It combines unambiguous current compiled staging options
(up to the existing five-mechanism bound), uses the existing application compiler
for a driver-only case, or proposes uniquely observed interfaces when all
constraints are satisfied. Unsupported/ambiguous cases abstain; a private case
label never selects a repair.

The D client may request at most one existing SDK validation within the same
300-second real wall budget, after rechecking the original entry/facts/provider
and clean source. Synthetic D contracts cannot call the SDK. Without an operator
callback, a proposal remains explicitly unexecuted. Callback exceptions preserve
an original result and consumed World count, with no automatic retry.

## Budgets, results and remaining gates

All model arms use the same pinned client/provider and real monotonic budget.
Shared original reads and Expert investigations consume the registered read-only
request budget, in addition to the model-decision cap. D records zero model
calls/decisions separately from its host compiler/validation operations.
Host callback exceptions and invalid model decisions retain distinct result
states and original per-turn artifacts; an exception cannot disappear as an
unreported episode or trigger another World.

Tests are synthetic contracts and original-input process checks are labelled as
operator-constructed checks. Neither constitutes a model result or a new physical
success. Independent post-harness cases, provider settings, four original entry
attestations and final exact-source/main acceptance still must be frozen before
the 25-allocation pilot can start. No causal Memory benefit is established.
