# ROS Expert Harness v1 — verified ROS engineering in simulation

The scoped engineering v1 provides read-only ROS diagnosis, original-source/Body
binding, known-mechanism conditional repair and independent protected SIM
verification. The final 2026-10-21 calibration stops at original-input entry
NO-GO: zero new model episodes/Worlds. This is not a new model-to-motion success,
general autonomous ROS expertise, hardware certification or a Memory-benefit claim.

## Existing workflow

1. Preserve original system snapshot, expanded URDF, navigation requirements and concrete Nav2/bringup inputs with hashes and original review time.
2. Run the existing offline `ros engineering-case` CLI; optionally request `--plan-staging`. [Exact runnable original-input example](reports/ros-expert-harness/FINAL_CLOSEOUT_2026-10-21/FC04_CLI_DEMO.md).
3. Review the stage-only diff, exact rollback, UNKNOWN constraints and all remaining proof obligations. A proposal applies nothing and confers no authority.
4. For a separately admitted physical protocol, bind a new owned World/run/immutable Body and obtain complete fresh L1. Historical source reviews and timestamps cannot be reused as current admission.
5. Submit authorized actions only through existing MCP `request_action` → rosclawd → Nav2. The Agent cannot create a permit, register an executor or open a ROS transport as a fallback.
6. Require canonical receipts plus independent target, contact, stop, lease-expiry and source-continuity verification. Nav2 SUCCEEDED alone does not verify the mission.

Steps 4–6 were not run in this final calibration because its original P1 entry
was not admitted. Historical verified SIM results remain bound to their original
source and run. The offline demo preserves its historical Source/lifecycle
unknowns and deliberately demonstrates why a static TF proposal is insufficient.

## Evidence checklist and supported boundaries

| Concern | Required evidence |
| --- | --- |
| Source/Body/run | Original assets, hashes, independent source binding and current immutable identity |
| TF | Correct frames, fresh transform, unique authority; no static-TF workaround for missing localization |
| QoS/sensors | Compatible endpoint types/QoS and complete fresh source observations |
| Lifecycle/localization | Current selected roles ACTIVE; failures/unknown captures remain visible |
| Geometry/navigation | Original collision envelope, costmap fit, valid route and bounded goals |
| Safety/result | Existing leases/watchdogs, independent contacts/stop/continuity and canonical matching receipts |

Five known mechanisms are supported: localization TF, declared scan bridge,
managed lifecycle list, geometry envelope, and an audited extra control route.
Source-consumer compatibility is an explicitly pinned static contract, not
runtime backend authentication. Unsupported/ambiguous evidence is not permission.
No new repair mechanism, Runtime, safety gateway or Memory store is added here.

The two environment seeds are not model sampler seeds. Host refusal, explicit
model abstention, evidence requests, invalid tools and budget exhaustion are
separate outcomes. Planned NOT_RUN cells cannot enter a model success rate.

See the [final study and evidence index](reports/ros-expert-harness/FINAL_CLOSEOUT_2026-10-21/README.md)
and [actual historical evidence viewer](reports/ros-expert-harness/FINAL_CLOSEOUT_2026-10-21/evidence-viewer.html).
The immutable committed acceptance snapshot cannot attest its own future merge;
the after-merge canonical attestation records actual main, first-CI/wheel and
independent hash review before marking delivery complete.
