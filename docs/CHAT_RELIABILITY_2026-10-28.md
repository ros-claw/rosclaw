本轮从 `797b8eba` 继续，优先处理普通聊天的取消、错误恢复和读文件体验。网球 demo 已暂停归档，未继续物理实验或训练。Pi 保持项目锁定的 **1.4.0**；没有为追求版本号而升级，也没有把尚未证明的问题归因于 Pi。

## 已复现并修复

| 场景 | 原行为 | 修改后的行为 |
| --- | --- | --- |
| Linux bash 运行的后代另建 session/进程组，用户取消 | 工具返回 `ABORTED`，后代仍运行 | 在 shell 存活期间捕获后代身份；取消和超时等待已捕获后代清理，报告清理状态；无关进程不受影响 |
| 后代身份无法确认，且仍占用 stdout 管道 | 清理已到时限，工具仍无限等待管道关闭 | 结束工具本地观察，有界返回 `unresolved`，明确可能仍有进程运行；晚到的 close 不再重复结束 |
| 模型请求已经以网络错误或限流终止 | 错误卡仍说“自动重试中”或“稍等自动重试” | 给出重新发送消息、检查网络或切换模型的实际恢复动作，不声称正在重试 |
| 同码 provider 错误被界面去重 | 后续错误的 activity 也被丢弃 | 界面继续去重，每次错误仍保留最多 1000 字符的诊断记录 |
| 行读取碰到大型单行 JSON | 提示换字节模式并一直拼到 EOF，没有可见的阅读成本 | 显示整文件字节数和默认分页估算；仅在需要完整文件时要求拼到 EOF |
| cursor 损坏、跨路径、跨实例或过期 | 部分分支只有错误原因，没有恢复动作 | 明确丢弃旧片段，在目标路径重新开始 bytes 读取，再使用新返回的 cursor |

读取的源字节、UTF-8 边界、cursor 绑定、EOF 和限额没有放宽。取消不改变正常成功命令有意留下后台任务的行为；非 Linux Unix 保留原进程组信号路径，Windows 保留原子进程路径。

Linux 跟踪仅检查已归属进程的 kernel children 列表，不周期扫描全主机 `/proc`。身份包含 PID、启动时刻、UID 和 boot ID。无法确认的进程不当作已停止，也不给未经确认的 PID 发信号。**采样不能证明捕获瞬间 double-fork 后立即逃逸的全部后代**；`captured_descendants_stopped` 只描述已捕获集合。这不是 OS 隔离或硬实时停止保证。

## 修复评测夹具，避免误报产品卡死

真实 24 行 PTY 测试最初失败：文件和命令完成，最终回复已持久化，但界面没有显示。原因是本地假 provider 对所有响应复用 `chatcmpl-fake`，触发正确的 `MIRROR_CONFLICT` 拒绝；不是模型没有完成，也不是新版 READ 损坏了消息。

测试 HTTP handler 现在每次响应生成唯一 ID，同一响应的所有 SSE chunk 共用该 ID。另一处 Progress 假模型只看最后一条消息，无法识别终态通知后追加的具身上下文；现改为匹配本轮最新用户事件，并测试新用户输入不会误匹配历史终态。**产品的身份冲突校验和真实进度/落盘断言都保留。**

- 全库 Python Ruff 仍报 275 个问题、611 个文件需要格式化；本次没有批量修改这些既有代码。修改的两个 Python 测试文件单独 lint 通过。不能把全库质量检查写成全部通过。
- 独立的原始脱组后代复现：修复前 `ABORTED` 后后代存活；修复后同类真实进程实验中后代已退出，未清理进程列表为空。另测 TERM 忽略、超时、无关进程保活、正常后台成功、PID 复用和身份读取失败；注入 EACCES 且后代仍持管道时明确返回未确认，测试随后精确清理自建进程。
